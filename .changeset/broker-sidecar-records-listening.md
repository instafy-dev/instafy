The tunnel broker can now tell whether a tunnel's site answers when the broker API does not run beside that tunnel's rathole. Before, `GET /tunnels/:id/probe` answered `listening: false` for every tunnel on another ingress, so in a split deployment a preview never left "issuing" even while it served traffic, and no tunnel ever became `active` in the broker. Now the ingress sidecar, which always runs beside its rathole, sends `HEAD /` to each of its live bindings every round and records what answered on the tunnel row (new nullable columns `listening_checked_at` and `listening_status`, migration `0014`). A broker on another node answers the probe from that record while it is at most three `RATHOLE_CONFIG_REFRESH_SECONDS` old. A broker beside rathole still dials directly, as before. A tunnel becomes `active` the first time its site answers and goes back to `requested` when it is re-issued, which also clears the record. Event hook deliveries the hook does not accept (a transport error or a non-2xx answer) are now logged as warnings with the event kind; before, they were dropped silently. No package changes.
