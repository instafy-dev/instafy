Instafy's browser asks less, and in Octo's words. Pressing a browser card that names its site now counts as the person's OK for that site for the rest of the chat: Studio names the sites of the cards the person pressed (`browserCardSites`, never a card it opened by itself or a teammate's press in a shared chat), the controller keeps that key only on the person's own signed-in message, and the runtime starts each of the chat's browser runs with those sites' `https` origins approved on the person's page, as an answered site prompt would; every step on the site still asks as before. A cookie or consent banner's refusal ("Reject all", "Only necessary") runs without a prompt in every mode: the shared classifier marks it only inside a banner the page describer recognises, never as a link or a form, and its step lets no form post leave the tab; "Accept all" and the same words outside a banner still ask. The browser view's prompt now reads like the chat's row ("Octo wants to use example.com." [Deny] [Allow site]) with the exact site or page under it, without "the AI agent", "Shared Browser is paused…" or the routine-browsing checkbox; the landing demo follows it. `STACK_BROWSER_HOST=1 pnpm stack:refresh` (or `stack:up` on a stopped stack) runs the local stack the way users' spaces run the browser (the base image with the on-demand browser host, and every space covered), so a local drive sees routine browsing as users do (DEV_SETUP.md); `stack:up` says when a controller or provider already running keeps its old settings. No package changes.
