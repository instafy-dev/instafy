`instafy login` and `instafy logout` now act on the selected profile's session: the profile named by `--profile`, else by `INSTAFY_PROFILE`, else by the nearest `.instafy/space.json`, and with none of those the default `~/.instafy/config.json`. That is the session commands run in the same folder and environment use, except `instafy space defaults refresh`, which takes the folder's profile before `INSTAFY_PROFILE`, and git's credential helper, which git runs from the repository's top folder. Before, a login with a profile selected by `INSTAFY_PROFILE` or a folder's binding took that profile's server but saved the new token to the default session, pointing it at the other profile's server, while the profile kept its old session; a logout cleared the default session instead of the selected one. Both now name an implicitly selected profile and what selected it. Logging out where no session is saved clears nothing and says so, rather than creating the file, and `instafy logout --json` reports the `profile` and `configPath` it acted on and whether it `cleared` a session. A runtime that `instafy runtime start` runs as a local process from a saved session re-reads that session when the controller refuses its token, and only if it is saved for the runtime's controller. Before, it re-read the default session, which for a selected profile is another session, perhaps another account's.
