A turn the routing preflight read as needing file changes is no longer failed when it legitimately changes nothing. It still gets one recovery pass that asks again for the changes or the concrete blocker; when that pass also changes nothing and lists no file, the agent's reply (an answer, a question for the person, or what blocks the work) is the turn's result instead of "Codex did not apply any workspace changes for a file-modifying request.", and the turn records a `codex/required-changes-not-made` artifact. Studio therefore no longer shows a failure and resends the prompt for such a turn. A reply that lists a file missing from disk still fails the turn. Every turn that saves to the workspace now lists the files it changed on disk among its receipts, also when no change was expected, so a skill pack's command that builds a site folder shows its files under the reply. No package changes.
