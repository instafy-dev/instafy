In the desktop app's Personal Browser, Desktop itself now keeps Octo off link-only sites and private addresses on every step it takes, in every tab, the person's own tab included. Sites on the web-research skill's link-only list (Booking.com, Airbnb, Amazon, Google search and Maps and others) are refused when Octo opens or navigates to them, follows a link to them or is redirected to them, before any prompt, and a page already on one is neither read nor used; the list is the skill's own file, bundled into the app, and without it Octo opens and reads no web page. Navigation Octo starts goes only to public addresses, also in the person's tab after `select_tab`, and a page or frame whose server answers from a private or local address is stopped before it renders, which also catches a name that changes its answer between Desktop's check and the connection. Your own browsing, once you take control back, is unchanged. No package changes.
