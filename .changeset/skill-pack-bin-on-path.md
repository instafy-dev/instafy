Skill packs can name their commands. A pack's `.instafy-pack.json` may declare `"bin": {"uw": "scripts/uw.mjs"}` (at most 8 commands; plain lowercase names, never a reserved one such as `node`, `git` or `instafy`; each a file inside the pack), and the command then runs by name in every shell, isolated tool worker and terminal the runtime starts, so a skill says `uw validate my-map` instead of defining a shell function before every command. Runtime images get one shim per command in `/usr/local/bin`, written by `scripts/install-skill-packs.mjs --install-root /opt/instafy/skill-packs`; the build fails when a login shell already finds a command of that name. Desktop and local runtimes write the shims at startup to a folder of their own at the end of PATH (so a pack never shadows another command), skip a name that is already on PATH, and remove the folder on exit. A name two packs declare goes to neither, and the space note in each pack's `SKILL.md` names the commands that are on PATH. No package changes.
