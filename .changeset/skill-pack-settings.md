Skill packs get their settings and a folder that outlasts the turn. A pack's `.instafy-pack.json` may list the settings its scripts read in `env`: exact names or `PREFIX_*` patterns. The maps pack lists `["UW_*", "INSTAFY_LOOKUP_*"]`. An isolated tool worker, which starts with a cleared environment, now gets the runtime's values of those names. It never gets a name that looks like a credential, an internal credential, or a runtime-owned name. A manifest whose patterns could reach process or runtime configuration (`PATH`, `LD_*`, `NODE_*`, `INSTAFY_*` other than `INSTAFY_LOOKUP_*`) is refused. Every turn also gets `INSTAFY_CACHE_DIR`, a folder per project on that runtime outside the workspace (`<workspace root>/.instafy/skill-pack-cache/<project>`). A pack keeps its caches, rate-limit holds and service health there instead of in a tool turn's fresh HOME or TMPDIR. An isolated worker may write that folder only when the runtime names it for the job, and never one the job's own environment names. No package changes.
