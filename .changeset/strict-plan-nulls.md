A team plan written under the strict plan output schema no longer has every lane stopped at once with "Write-scope coordination required" (invalid_write_scope). That schema makes each optional field required and nullable, so the model writes null for each one it leaves out, such as a lane's `readOnlyPaths`, `ownedPathGlobs` or `rationale`; the runtime passed those nulls on, and the controller rightly refuses a null where it expects a list of paths. The runtime now reads every null field in a plan action as the field being left out, at every depth and whatever wrote the plan (write scopes, `runtimeRouting`, `presentation`, `handoffPaths`, and alias keys such as `write_scope`), before it sends the plan; a field holding an object of nothing but nulls, such as a write scope with every field null, is left out the same way. A null entry inside a list, and any non-null value of the wrong type, is kept, and the controller still refuses it. The controller is unchanged. No package changes.
