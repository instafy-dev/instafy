On a browser session machine, Instafy's browser now starts again when its Chromium exits, instead of staying gone until the machine restarts. runtime-agent watches the boot-time Chromium once it has seen it run and starts it again through `runtime-entrypoint launch-chromium` after 1, 5, 15, 30 and then 60 seconds for exits in a row, at most five times in ten minutes; past that it gives up, writes the reason to the browser's warning file and refuses Shared Browser jobs with it. While Chromium is not running, origin's page, page-command, pixel and input routes answer 503 `browser_restarting` (with `Retry-After: 2`) or `browser_stopped`, and Studio's browser view says "Instafy's browser stopped. Starting it again…" and connects once it runs, or "Instafy's browser stopped and did not start again. Restart this space's machine to open it." without a Try again. The machine's logs now tell the two causes of a browser that did not open apart: `event = "chromium_exited"` with Chromium's exit status or signal, uptime, OOM kills and whether a run held the browser, and `event = "runtime_exit"` with the reason a turn's end could not confirm its browser tools stopped and the browser's state at that moment. No package changes.
