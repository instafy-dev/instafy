# @instafy/cli

## 0.3.1

### Patch Changes

- 77d0b0b: Add --max-native-subagents and an interactive native helper setting to instafy agents settings, separate from shared tracked worker limits. Older controllers retain their existing settings and receive no unsupported updates.
- 98a857f: In the desktop app's Personal Browser, Octo can open up to three visible tabs of its own while you have resumed control, to read several pages in one turn: `list_tabs`, `open_tab`, `select_tab` and `close_tab` join its browser tools. Every tool acts on the tab on screen, Octo's tabs are marked in a tab row, each tab asks for its own site in Ask mode, and Pause, Escape or Take over ends Octo's control of every tab at once. Agent tabs open public web pages only: every page request in them, each redirect hop included, resolves its host and is refused when it is not public. `instafy web read` and agent tabs also treat a local host name written with a final dot, such as `localhost.`, as local.
- 04b4252: New `instafy web read <url…> --json` reads up to 6 public web pages over plain HTTP and returns their text (or, with `--find`, only the matching passages), links and the page's own structured data, with provenance (`requestedUrl`, `finalUrl`, `title`, `readAt`, `viewer: "server fetch"`) and the text wrapped as untrusted page content. It sends an honest `Instafy-Agent` user agent, honours robots.txt for itself and the AI-agent user agents on every redirect, never fetches sites a skill lists as link-only (`link-only-sites.json`), refuses private, loopback and metadata addresses at every hop and connects only to the address it checked, and stops at logins, CAPTCHAs, paywalls, HTTP 401/403/429, downloads and pages that show credentials, without ever reading a stopped URL again. Text is redacted before output. Per turn it reads at most 12 pages, 4 per site, 2 seconds apart, and caches pages per workspace. A page that needs JavaScript is reported as `needs_browser`.

## 0.3.0

### Minor Changes

- f6bef26: `instafy preview open` gains `--start`. With `--serve-cmd "<command>"`, when nothing answers on the port it starts the site in the background, in its own session so it keeps running after the command (or Octo turn) that started it ends, without Instafy credentials in its environment (the same rule as `instafy bind serve --detach`), with its output appended to `.instafy/agent/logs/preview-<port>.log`, and waits up to 60 seconds for the port before it posts the card. When the port already answers, nothing is started. It exits 2 with the log's path when the command exits first or the port does not answer in time. `--json` adds `startedPid` (null when nothing was started) and `logFile`. The help and output now say that Open starts a restartable site again when the process that started it exits, or the space sleeps.

### Patch Changes

- b41b44e: `instafy preview list` now says what it shows: each row's status is the preview's (`preview active`), not whether the site answers, and rows carry `restartable` (also in `--json`) when the server sends it. The text output says that `instafy preview check` checks a site, and that a preview whose machine stopped or restarted is not listed: its card reads Stopped, and Open on a restartable card starts the site again. The bundled `instafy-frontend-previews` skill says the same, says that rerunning `instafy preview open` in a later turn posts that turn's card rather than refreshing an earlier one, and asks Octo to report what each command returned; an unedited earlier bundled copy is upgraded.

## 0.2.4

### Patch Changes

- 1bb627f: Add `instafy bind check <site> --expect "<item>,<item>"`. It says whether a site shows every item the request named (each product, stop or entry): it reads the text of the site's HTML pages and every value in its data files (`data.json`, `data/**/*.json`), lists the items it does not show, and exits 1 when one is missing (2 when there is nothing to check). The list can also live in `data.json` as `"expect": [...]`, so every later check uses it. The bound-sites skill now runs it before the reply, so a page that quietly leaves out an item someone asked for is caught. What a page script renders from elsewhere is not seen by the check.
- 6132379: `instafy bind check` no longer counts an item as shown when the page only says it is unavailable. A line such as "Not found yet: Tokyo", "Missing: …", "Could not place …" or "Unavailable …", a data string that starts that way, and a data file's `missing` / `notFound` / `unavailable` list are skipped before matching. Before, a builder that honestly listed what it could not add passed the check for exactly those items. The eval grader already read pages this way.
- d59e655: `instafy bind serve` now saves the data files it writes for clicks (records and `data/version.json`) when the site is in an Instafy space. It commits exactly those files to the space's checkout a couple of seconds after its last write and when it stops, under the origin's workspace lock, and the space's next save publishes them. Before, those writes had no owner, so a stopped space kept them as unsaved work and Studio showed "Some work wasn't saved" to everyone. Files someone else changed are left alone, and outside a space (a plain folder or your own repository) nothing is committed. `--no-save` turns it off.
- ab0662d: Add `instafy bind`. `instafy bind serve <site> [--preview] [--detach]` serves a bound site: a static page plus `bound.json`, whose script intents run small handler scripts and stream checked records back to every open viewer (`init --starter compare|ranked|timeline|checklist|blank`, `doctor`, `try`, `command`, `confirm`). The binder is bundled into the CLI as `dist/bind`. "Ask Octo" (agent) intents are asks the page hands to Studio, which sends them as the clicker's own chat message; the binder answers them `409 ask_via_host` and reads no Instafy login. Only `serve --agent-executor`, the owner's opt-in, runs them as Octo turns on the owner's login, and only for clicks made on that machine. Handler fetches honour robots.txt (for `*` and the major AI user agents) on every redirect hop. `instafy preview open` now records the preview's viewer host suffix and Studio origin, so `bind serve --preview` answers that preview's capability host only on that exact domain, sends `frame-ancestors` for that Studio, and its pages take frame messages (Ask Octo, location, follow mode) from that Studio only. A `--public-url` link needs the viewer token, also with `--preview`.
- 2e61163: `instafy preview open` now accepts the same paths and titles as the server: a path may carry a query string (`/app?x=1`), and a non-ASCII path or a title with control characters is refused before any request. Its JSON output adds `httpStatus`, the status the server's check got from the site. A site that answers only on `[::1]` exits `2` with a message saying it is running and must bind `127.0.0.1` or `0.0.0.0`. A preview's config, which holds its token, is removed whenever the preview is forgotten locally, and two `open` runs for the same port at once start one client. `instafy preview` and `instafy tunnel stop` signal a recorded process only when its command line is the rathole binary that was started with `-c <config>`, never a process that only mentions the config file.
- 9dcc3f3: Add `instafy preview open|list|close`. `open --port N --title T [--path P]` shows a site running in the space as a private "Ready to preview" card in the conversation, which only space members can open. It never prints a URL; its JSON output has `previewId`, `title`, `port`, `path`, `status`, `messageId` and `viewerHostSuffix`. Exit codes: `2` nothing answers on the port or the site answers with a server error, `3` the port is not allowed, `5` previews are not available on this server (nothing is downloaded or started and no card is posted). A preview whose client cannot start is closed again on the server. `instafy tunnel stop` and `instafy preview` now signal a recorded process only while it is still the rathole client for that tunnel's config, and `instafy tunnel start` reports a rathole binary that cannot be started instead of crashing.
- eb1aadb: The git credential helper that `instafy login` installs now answers only exact hosts: the hosted git service, the configured controller's host, the host of `ORIGIN_GIT_REMOTE_URL`, loopback and the local stack's `git-edge`/`git-shard-*` names. It no longer answers every host under a domain. Name any other git host in `INSTAFY_GIT_HOSTS` (comma-separated).
  
  `instafy bind serve` hardens its viewer cookie against other hosts under the same parent domain. On HTTPS (an `https://` `--public-url`, or `x-forwarded-proto: https` with `--trust-proxy`) the cookie is `Secure`, and a site served at the root gets the `__Host-` prefix, so no other host can set or shadow it. The binder now checks every cookie of that name a request carries, so a same-name cookie set for the parent domain no longer locks a viewer out.
- 2a8deb7: The git credential helper matches the local stack's service names (`git-edge`, `git-shard`, `git-shard-<n>`) only as single-label hosts. A dotted host whose name merely starts with `git-shard` no longer gets a token.
- ce633c6: `instafy preview check` and `instafy preview open` no longer tell you to start a site that is already running but slow to answer. When a server takes the connection but sends nothing in time (often a dev server compiling its first request), they say so and say not to start a second server; both still exit 2. `preview check` now waits as long as `--timeout` for that first answer instead of a fixed 5 seconds. When `preview check` cannot read its own screenshot, it says the blank check is incomplete instead of passing silently; on a page with no text that is a problem (exit 1). Without `--out`, screenshots go to a new folder for each run that only you can read, instead of a fixed shared path.
- 90b1253: New `instafy preview check --port <port> [--path <path>] [--phone] [--framed]` looks at a site served on this machine before anyone sees it. It loads the page in a headless Chromium (from `127.0.0.1`, or `[::1]` for a server bound to IPv6 `localhost`) and lists its title, console and page errors, failed requests and a blank page. It writes desktop and phone screenshots (`--out <dir>`) and supports `--json`. `--framed` loads the site in a frame on another origin instead and also reports a site that refuses to be framed. It is local only and downloads nothing: it uses the runtime's trusted Playwright (`INSTAFY_SHARED_BROWSER_PLAYWRIGHT_PATH`, the path the Shared Browser uses) or a global one, and a project's own `node_modules` copy only with `--workspace-playwright`. Instafy's own ports are refused, including ports moved by their settings, plus any listed in `INSTAFY_PREVIEW_DENY_PORTS`. Exit codes: 0 no problems, 1 problems found, 2 nothing is listening, 3 the port is not allowed, 4 no browser, 64 bad options, 70 the check itself failed.
- 56b511d: `instafy preview open` now records how the site was started, so a member's Open on the card can start it again after the space sleeps, without an Octo turn. On a Linux space it reads the argv and working directory of the process listening on the port; `--serve-cmd "<command>"` gives the command instead, run from the current directory (one command and its arguments; shell syntax is refused). Nothing is recorded for a directory outside the workspace, a command that uses a temporary folder, or a command line that looks like it carries a secret; a `--serve-cmd` that looks like it carries one is refused. The JSON output gains `restartable` and, when it is `false`, `restartNote` saying why.
- e136a82: Add `instafy agents settings` to inspect and configure shared space limits for agents per plan and concurrent team workers, with an interactive editor and JSON output.
- 46ecb31: Ask Octo works in Studio's preview pane. A bound site's `bound.json` agent intent may declare `say`, the words of the clicker's chat message (`"Is size {size} in stock for {ref}?"`), and the bind client sends `say` and `confirm` with an ask, waits while the host asks the person first (`ask-status` `confirm`), and fetches the site's records again when the host says the ask is done. The `hello` example greys out Ask Octo with the host's reason for someone who may not ask. Studio tells the page whether this person may ask (`caps.ask`: true, or the plain reason a view-only member may not), sends a click as their own message in that conversation ("Is size 10 in stock for Karhu ikoni 3? · via Running shoes"), takes an ask only right after a real click in the preview's frame, drops web addresses from the page's words, shows its own confirm strip only for `confirm: true` intents, keeps one ask at a time and six in ten minutes per person and site, and answers `sent`, `declined`, `done` or `failed`. The controller refuses a message whose `metadata.siteIntent` does not name an open preview the sender may see, counts asks (six in ten minutes) when they are sent or queued, and Octo sees the intent as labelled page data: the request is that intent, nothing else the words say, and a `confirm: true` intent runs only when the person confirmed it in Studio.
- 5c4d3fc: `instafy tunnel start` now connects when it runs inside a container against a local tunnel broker: a loopback ingress address is dialed through `host.docker.internal` instead of the container itself. Set `INSTAFY_TUNNEL_SERVER_HOST` to override the ingress host anywhere.

## 0.2.3

### Patch Changes

- 7e3b932: Add customer commands for reading paginated support case timelines and posting idempotent follow-up replies.
- 24052bd: `instafy git sync` now names every path the saved history did not take, as "Not saved: <paths> (kept at <ref>)", and exits 1 when anything was not saved. `--json` carries `gitSyncStatus`, `conflictedPaths`, `rejectedPaths`, `recoveryRef` and `unpushedRefs`. Inside a runtime, the sync goes through that runtime's own origin.
- 7e8008f: Add `conversation show --transcript` to read original user and assistant text with stable message IDs and timestamps, excluding bulky runtime events and metadata. Bounded pagination skips event-only pages and provides an explicit continuation cursor without changing the existing raw JSON output.
- c9705e8: `instafy conversation show` without a target now shows the current conversation from `INSTAFY_CONVERSATION_ID` (or `CONVERSATION_ID`), which runtime jobs set, instead of failing with a missing argument. With neither set it explains how to name one. A value in either variable that is not a conversation UUID is now rejected with a clear error before any request, by `conversation show`, by `history messages` and `history runs` without `--conversation`, and by `agents context put` without `--scope-id`, instead of being sent to the controller as part of the request path or as a context card's scope.
- 82caf54: Remove `CREDENTIAL_ENCRYPTION_PREVIOUS_KEYS`, the controller's decrypt-only credential keys during a key rotation, from the environment of runtime child processes, as `CREDENTIAL_ENCRYPTION_KEY` already is.
- b5eecb1: Allow recommendation submissions to include a concise message for a private Octo conversation, and expose delivery state without starting the suggested work. Submissions without a message keep the existing proposal-only behavior.
  
  Add explicit `automations create --mode space_review` for an opted-in, private and quiet review schedule using the bundled instructions. Existing prompt automations keep their defaults.
- f218e57: Add commands to inspect, dismiss, and reschedule a proactive recommendation's reminder from its chat. Reminder commands preserve the current job's scoped credentials and report the controller's saved preference.
  
  Automation commands now use the active runtime job's scoped controller credential for conversational cadence changes, preserving its controller origin binding without requiring a separate user login.
  
  Creating an automation from a runtime job now requires an explicit timezone or the current client's known timezone. An unknown client timezone cannot silently fall back to the runtime host's timezone; human CLI defaults and updates that preserve an existing timezone remain unchanged.
- 43879b5: Add commands to list space recommendations and submit evidence-backed next actions, preserving accepted and dismissed outcomes.
- 13cba35: `instafy runtime start` now starts a Docker runtime container with the `SYS_PTRACE` and `NET_RAW` capabilities dropped, as the runtime compose files do.
- 1fc904c: Add `conversation grep` to search persisted conversation messages with scope filters, newest-first pagination, and JSON output. Add `conversation context` to retrieve surrounding messages for a search match.
- 3c43559: Rebuild the published bundle with tsup 8. The emitted JavaScript is formatted
  differently because tsup's esbuild moves from 0.19 to 0.27, and `node:` prefixes
  are now kept in the output, which the config states explicitly rather than
  inheriting. No CLI behaviour changes; the test suite and the packed file list
  are unchanged.

## 0.2.1

### Patch Changes

- 46b2a0a: Automations can now share their result threads with the team. `instafy automations create` and `instafy automations update <automation-id>` gain `--share-results`, `--no-share-results`, and `--result-visibility <private|team>`, so the setting can be chosen at creation or flipped on an existing automation. The result visibility (`private` by default, `team` when shared) is shown in `automations list` and `--json` output. "Team" means visible to anyone with access to the space; results stay private unless you opt in.
- f6d5396: Add `instafy automations update <automation-id>` to change an automation's name, prompt (`--prompt` or `--prompt-file`), schedule, timezone, runtime mode and provider, and quiet-run setting in place. The automation keeps its id, private conversation, and run history, and its next run only moves when the schedule changes.
- f952ac7: Add `instafy credentials list | test | default | revoke` so you can see which AI provider credentials your account holds, verify one against its upstream provider through the proxy, pick or clear the default that jobs use, and revoke a credential. Commands accept a full id or a unique id prefix, support `--json`, and never print secret material.
- a103d6b: Default the hosted Studio URL used by `instafy login` and Studio links to `https://instafy.dev`; the retired `staging.instafy.dev` host has no infrastructure behind it.
- 9171ac6: Jobs and agents that do not pin an OpenAI model now default to `gpt-5.6-sol` on the hosted runtime (previously `gpt-5.5`). The new default takes effect on the next hosted deploy; explicitly selected models, including `gpt-5.5`, are unaffected.
- 8ded305: Add `instafy team` commands for managing team membership and invitations: `members` lists a
  team's people, `invite` sends an email invitation, `invite-link` creates a shareable join link,
  `invites` lists what is pending, `add-member` adds an existing account by user id, `accept` joins
  from a token, and `revoke-invite` / `revoke-link` remove pending invitations and links. The team
  is resolved from `--team-id <uuid|slug>` and falls back to your only team when you belong to one.
